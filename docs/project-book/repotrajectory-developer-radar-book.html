01 / Product transformation

From analytics to decisions

RepoTrajectory helps developers discover open-source tools, evaluate whether they fit a project, compare alternatives, and understand what changed after a decision.

Discover→Understand→Compare→Decide→Watch
Developer questionImplemented surface
What should I investigate?Discover homepage, Scout, eight rule-based topic collections.
What is it and how can I try it?Deterministic brief, README/project statements, package and documentation links.
Does it fit my situation?Structured comparison of known language, licensing, package ecosystem and activity facts.
Why was I interested?Browser-local watch reason, blocker, tags and original save time.
What changed since then?Evidence-linked release, security, discussion, license and adoption events.

Keep the dimensions separate

GitHub attention, package downloads, maintenance, delivery, community discussion and security evidence are not combined into a universal score. Existing advanced analytics remain accessible through progressive disclosure.

This is an implemented beta, not the completion of every item in the original brief. Deployment suitability, watch-driven scheduling, official RSS and vulnerability-fix reconciliation remain explicit gaps.

How to use this book

Pages 3–7 explain trust, architecture, sources, APIs and product interactions. Pages 8–10 cover operations, verification and the maintenance handoff. Source code and migrations take precedence over this snapshot.

02 / Trust repairs

Unknown stays unknown

Scout now follows the correct identity relationship

External activity references the internal candidate primary key—not GitHub's repository ID. Scout joins the candidate relationship and filters by the stable GitHub ID.

CatalogRepository.github_id
        = RepositoryCandidate.github_id
RepositoryCandidate.id
        = ExternalRepositoryActivity.candidate_id

A regression test separates internal ID 42 from GitHub ID 60001 and includes a misleading candidate with internal ID 60001. This prevents accidental success when fixtures reuse the same number.

No pseudo-semantic search

The fallback provider returns no embeddings. Without a real provider, search uses lexical retrieval and reports semantic unavailability. The semantic-v2 namespace avoids old hash vectors and cached pseudo-semantic results without deleting historical data.

Real vector retrieval is restricted to matching model/version data. A nested database transaction isolates vector errors so the lexical branch can still return useful results. Search is bounded to 500 query characters and 100 requested results.

No invented UI certainty

Fabricated coverage and health defaults were removed, including Scout's 70% fallback. Zero remains zero; missing information is shown as unknown or insufficient evidence. Where a value measures available evidence, the UI calls it “Evidence coverage,” without pretending the methodology became statistically calibrated.

A direct project statement, a derived metric and an attributed discussion are different kinds of evidence. Missing evidence is not negative evidence—and none is a license to fabricate a balanced-sounding claim.

Preserved invariants

Stable numeric repository identity; bounded collection; PostgreSQL-backed deduplicated, leased jobs; no raw GH Archive payload persistence; server-only secrets; optional hosted AI; migration-managed schema.

03 / Architecture & data

Collect once. Reuse evidence.

Next.js renders typed product contracts from FastAPI. The existing collector enriches selected repositories through the PostgreSQL job system. PostgreSQL also stores shared source cache state, normalized evidence and optional pgvector data. Caddy remains the deployment entry point.

Read path

Browser → Next.js / FastAPI v2 → PostgreSQL → brief, comparison, changes.

Collection path

Durable jobs → collector → bounded adapters → verified links → normalized evidence and snapshots → deterministic events.

Public reads do not call external providers or enqueue collection. Local watch reasons stay in the browser; watching currently does not promote a repository into deeper collection.

Deletion and replay

Catalog deletion cascades to its evidence records. Expiring an evidence item can leave a change event with a null evidence reference. Unique fingerprints and repository-level locking make replay safe. Indexes support repository/time queries and cleanup.

Fresh installation repair

Migration 0001 now uses frozen original-schema SQL instead of importing today's ORM models. This avoids creating future tables too early or referencing pgvector before its extension exists.

04 / Source adapters

Linked evidence, not name guesses

Package discovery starts with explicit npm/PyPI URLs in a project's README. Registry repository metadata must resolve through GitHub to the same numeric repository ID. Conflicting repository links remain unresolved. A shared name is not enough.

Common transport safeguards

Fixed HTTPS hosts, 12-second timeouts, at most three attempts with backoff, rate-limit-aware rescheduling and a 2 MB response ceiling. Successful normalized state is reused across users. Failed refreshes preserve the previous successful facts and expose degraded status.

“No known findings returned for the checked package version” is valid. “This project is secure” is not. HN stories are attributed discussion evidence, not verified user experience or a quality signal.

Provider hosts: registry.npmjs.org, api.npmjs.org, pypi.org, pypistats.org, api.deps.dev, api.osv.dev and hn.algolia.com. HN uses its public search endpoint; there is no paid search service dependency. Curated RSS is deferred.

05 / Product contracts

Briefs and contextual comparisons

A practical brief, with visible limits

The brief composes attributed description/README material, language, license, topics, package links, GitHub attention, last push, downloads, security checks, evidence freshness and changes. It does not invent a tutorial, capabilities, prerequisites or disadvantages. Advanced analytics stay available below the product-oriented summary.

Compare for my situation

The API accepts two to four distinct GitHub IDs; the interface compares two projects. Constraints cover primary language, exact license identifier, package ecosystem and recent push activity. Results distinguish matches, differences and unknowns. Deployment requirements remain unknown when unsupported.

Free-text context is retained for the user, not automatically interpreted. Even with an AI key, the current brief and comparison remain deterministic and do not generate a recommendation.

06 / Returning value

Remember the reason. Inspect change.

“Interesting for a RAG project, but I need to see stable releases.”

A watch retains the developer's original reasoning while the server supplies independently collected changes.

Up to 100 browser-local watches store GitHub ID, repository name, reason, optional blocker, tags and timestamp. Editing preserves the original watch time. Clearing browser storage loses these entries. There are no server accounts or notifications in this beta.

Event familyEvidence rule
Release / discussionOriginal publication time, with a source link.
Vulnerability discoveredNew observed advisory for a checked package/version; observation time.
License changedKnown-to-known transition. Missing license is not a change.
Dormant / resumedRecorded push freshness; default dormancy threshold 180 days.
Package adoption movementDefault weekly-download movement ≥50% and ≥1,000 downloads.

Initial metric observations establish a baseline. Tiny fluctuations do not create events. The change feed discloses its retention window and truncation. It does not claim that a saved blocker has been semantically resolved.

Eight initial technology collections

Agent frameworks · RAG infrastructure · AI evaluation · AI observability · Model serving/inference · Vector/search infrastructure · MCP/agent tooling · Developer AI infrastructure.

Lightweight rules match descriptions and topics, with stable-ID inclusion/exclusion configuration. Results are bounded to 60 and ordered by recent push. These are discovery collections—not calibrated emerging-project or maturity rankings. The schema is not restricted to AI software.

Coverage is limited by collection, not by the number of watches. A cold repository may have few changes available. Watch-driven enrichment remains a next step.

07 / Budget & operations

A useful product without paid AI

No AI configured

Lexical search, evidence, deterministic briefs, structured comparisons, Scout fallback, topics and local watch feeds remain usable.

Optional AI configured

Budgeted provider operations and evidence-fingerprinted Scout caching. Real embeddings only; no synthetic fallback vectors.

Application-level AI controls

AI_ENABLED gates hosted AI. Defaults allow one concurrent call, 100 daily requests and 300,000 conservatively reserved tokens monthly. PostgreSQL advisory locking coordinates reservations across workers. Failed requests retain reservations; ledger failure denies optional AI, not application reads.

Usage records can include actual tokens and configurable price estimates. Unknown cost stays unknown. Artifacts are fingerprinted by evidence/request, model, provider and prompt version. No key values belong in this book, browser bundles or Git.

Bounded storage and refresh

ResourcePolicy
Deep enrichmentUp to 200 repositories daily, with source-specific cache intervals.
Evidence / changes180 days and at most 200 rows each per repository.
Snapshots / inactive source state180-day retention; snapshots deduplicated daily.
AI usage / artifacts60 days.
Stored excerptsEvidence excerpts bounded to 1,200 characters; no full social threads or articles.

Single-VPS operating model

Caddy, Next.js, FastAPI, PostgreSQL and one collector. Target 4–8 GB RAM and 2–4 shared vCPU. A €10–18 hosting allowance leaves limited backup headroom under €20/month; this is a planning estimate, not a vendor quote or measured capacity guarantee.

Unused Redis was removed from Compose without deleting its existing volume. Restore now stops on SQL errors, uses a transaction and checks schema revision plus all public table counts. Failed rehearsals are retained for diagnosis.

08 / Running & verification

Run locally and know what was tested

Install Docker with Compose and start Docker. From the repository root:

./run.sh
# On first run: edit the generated .env.
# Set a read-only GITHUB_TOKEN. AI keys are optional.
./run.sh admin-password
./run.sh
./run.sh status
./run.sh logs
# Stop without deleting volumes:
./run.sh down

The launcher chooses a free port from 10100–10110 and prints the URL. The prior delivery verification used http://localhost:10100. For explicitly offline AI, use AI_ENABLED=false and leave both AI key variables empty.
